# Lessons

Durable, hard-won facts. Not a log, not a diary, not debug output.
A lesson earns a line here only if it would otherwise be rediscovered the expensive way.

| # | Lesson | Origin |
|---|---|---|
| L-001 | `reference/nArchitecture` is a nested git repo with its own history. Running git commands from the workspace root will not see it, and it must never be committed into this repo's tree as source. | workspace scan, 2026-09-23 |
| L-002 | YouTube Data API v3 bills `search.list` at roughly 100x a `videos.list` call in quota units. Search-heavy track pickers exhaust a default daily quota fast. Cache aggressively. | [[ADR-0003-music-provider-youtube]] |
| L-003 | Publicly committed credentials are an automatic project failure in this subject, not a deduction. `.env` is git-ignored from the first commit, not retrofitted. | [[subject-requirements]] |
| L-005 | BCrypt truncates its input at **72 bytes**. Two different long passwords then hash identically. Enforce 12-64 characters and a 72-byte UTF-8 check in validation — do not rely on the library to complain. | [[ADR-0007-password-hashing-bcrypt]] |
| L-006 | An OAuth 2.0 **access token** says what the bearer may do, not who they are, and may have been minted for another app. Identity comes from a validated OIDC **ID token** with `aud` and `nonce` checked. | [[ADR-0008-oidc-social-login]] |
| L-007 | Facebook is not uniformly OIDC: Limited Login issues an ID token, classic Facebook Login does not. Google is full OIDC. The integration must branch — assuming symmetry produces a broken or insecure path. | [[social-oauth]] |
| L-008 | Microsoft's CA analyzers cannot express method **length** or method **count**. `SonarAnalyzer.CSharp` supplies S138, S1448 and S104. A limit written only in a document is a suggestion. | [[ADR-0009-code-quality-gates]] |
| L-009 | ASVS is CC BY-SA 4.0. Verbatim redistribution needs attribution and the licence file alongside it; adapted text carries share-alike. Reference requirement ids instead of copying requirement text. | [[owasp-provenance]] |
| L-010 | Vercel cannot host this API. It is serverless functions plus static hosting: ASP.NET Core needs a long-running process and SignalR holds persistent WebSocket connections. .NET is not a first-class Vercel runtime either. Docker-image hosts (Fly.io, Railway, Render, Azure Container Apps) are the viable class. | [[ADR-0015-hosting-and-deployment]] |
| L-011 | Supabase free projects **pause** after a period of inactivity. A paused project on defence day is a dead demo. Touch it beforehand and keep the local PostgreSQL container as a fallback — same engine, same migrations. | [[ADR-0016-supabase-plan-region]] |
| L-012 | Client-reported GPS is evidence, not proof. Server-side geofencing can only check what the client claims. A venue-issued short-lived code raises the cost far more than any coordinate validation can. | [[ADR-0014-location-time-licence]] |
| L-013 | "Who is playing what right now" is its own aggregate. Hanging now-playing off `Event` and control off `Device` leaves delegation unconnected to the thing being played, and a peer evaluator will ask what a delegate actually controls. | [[ADR-0017-playback-session]] |
| L-014 | A backend cannot observe audio. Advancing a queue on a server-side `durationSeconds` timer drifts on pause and buffering; the client reports *when*, the server decides *what*. Make the advance call idempotent on the expected current track or a retry silently skips a song. | [[ADR-0017-playback-session]] |
| L-015 | SignalR hub methods bypass the MediatR pipeline, so a REST-only audit behaviour silently misses every hub action. A hub filter is needed, and client context must be captured at the handshake because a hub invocation carries no HTTP headers. | [[ADR-0019-hub-action-auditing]] |
| L-016 | `ab` cannot measure WebSocket. For a SignalR system the load tool choice is constrained by the realtime surface, not by REST throughput. Gatling is both named in the subject and WebSocket-capable. | [[ADR-0018-load-testing-tool]] |
| L-017 | MediatR and AutoMapper moved to a commercial licence (LuckyPennySoftware) with a free tier for small-scale use. "Everyone uses it" stopped being a sufficient reason to add a .NET package — check the terms and record the check. | [[ADR-0021-backend-dependency-set]] |
| L-018 | An in-memory-only catalog cache re-burns the YouTube quota after every container restart, and restarts cluster right before a demo. Persist the cache in the database and keep memory as L1. | [[ADR-0023-catalog-cache]] |
| L-019 | Never let a scheduler be the only thing enforcing expiry. Check the lifetime at the point of use; a background sweep is hygiene, not security. A stopped timer must not turn a stale token into a valid one. | [[ADR-0024-expiry-and-cleanup]] |
| L-020 | Submodules are a submission risk at 42: a stale pointer or a forgotten `--recursive` means the evaluator sees missing code. One repository, one clone, one submission. | [[ADR-0020-monorepo-layout]] |
| L-021 | An unattended agent needs a git protocol, not just a prohibition. Branch and commit per spec gives per-unit rollback; "never commit" turns five cycles into one unreviewable pile. A clean tree is a precondition, not a nicety. | [[ADR-0025-agent-git-protocol]] |
| L-022 | Name configuration after the role, not the vendor: `DATABASE_URL`, not `SUPABASE_DB_URL`. A variable named after a provider couples the application to it for no reason. | [[ADR-0026-environment-bring-up]] |
| L-023 | Branch protection with `enforce_admins: false` is decorative when the agent runs with the repository owner's token — an admin bypasses it. Admin enforcement is what turns the rule into a mechanism. | [[ADR-0027-agent-push-and-pr]] |
| L-024 | A draft pull request is the cheapest human gate in an automated pipeline: GitHub refuses to merge it, so "ready for review" becomes an explicit human decision with no extra tooling. | [[ADR-0027-agent-push-and-pr]] |
| L-025 | A non-interactive agent (`claude -p`) cannot ask for permission, so an ungranted write is silently refused and the whole cycle ends having produced nothing. Pass a settings file with scoped permissions and `--permission-prompts none`, or unattended runs only look like they are working. | observed 2026-09-24, first S1 cycle |
| L-026 | In Claude Code permission settings, path rules must be written as `Edit(path)`. A `Write(path)` rule is silently ignored — `Edit` rules cover every file-editing tool. A deny list written with `Write(...)` is protection that does not exist. | observed 2026-09-24 |
| L-027 | A required status check combined with a path filter blocks a pull request forever: the check never runs, so it can never pass. Either the required workflow has no path filter, or a same-named no-op job covers the excluded paths. | observed 2026-09-24, PR #3 |
| L-028 | A control file the tool watches for must be git-ignored. `.agent/STOP` was not, so pulling the cord dirtied the tree and the driver — which refuses to start on a dirty tree — would not start again. | observed 2026-09-24 |
| L-029 | A spec's Files table is the real design review. Three implementation cycles stopped before writing a line, each on a table that looked complete: a base type that forced an outward reference, an abstraction in the wrong assembly, a handler with no repository, a validator with no behaviour to run it. Walk the table against the dependency graph before approving it, not after. | observed 2026-09-24, SPEC-002 |
| L-030 | Copying a reference architecture's folder shape imports its dependency edges too. nArchitecture puts the entity base in Core.Persistence and has Domain inherit it; our dependency rule forbids exactly that. Decide which one wins before the first entity, not during it. | [[ADR-0028-domain-owns-its-base-types]] |
| L-031 | The `.editorconfig` private-field naming rule covers `private const`, so `IDE1006` fires on a `private const Foo` that is not `_camelCase`. Declare such constants as method locals or `internal` rather than weakening the rule. | observed 2026-09-24, SPEC-002 |
| L-032 | Pin `Microsoft.EntityFrameworkCore.Design` to the EF Core version the Npgsql provider depends on, not the newest published one. A mismatch surfaces as `MSB3277`, which reads like a restore problem and is a version-alignment problem. | observed 2026-09-24, SPEC-002 |
| L-033 | `dotnet ef` resolves the Design package from the **startup** project, not from the project holding the `DbContext`. `PrivateAssets="all"` on the persistence project is exactly what stops it arriving. Reference it on both; it ships no runtime code either way. | [[ADR-0028-domain-owns-its-base-types]], SPEC-002 |
| L-034 | A protocol that leaves blocked work uncommitted deadlocks a driver that refuses to start on a dirty tree. Preserve evidence in git with a `wip:` commit, not in the working tree. Same class of mistake as a control file that is not git-ignored. | observed 2026-09-24 |
| L-035 | An `internal` type is fine for dependency injection; an `internal` constructor is not. `A suitable constructor for type '...' could not be located.` surfaces at container validation, which `ValidateOnBuild` runs at start-up in Development — and which `dotnet ef` also triggers, because building the migration host builds the container. | observed 2026-09-24, SPEC-002 |
| L-036 | Every `dotnet ef migrations add` in this repository needs a formatting pass before the build accepts it: the generated file uses a block namespace, omits null checks and writes an `Up` well past the 40-line limit. Reformat and split into helpers; the emitted SQL must stay identical. Budget one self-heal cycle for it, and never reach for a severity. | observed 2026-09-24, SPEC-002 |
| L-035 | Claude Code Bash permission rules match a whole-command prefix, so a partial word such as `Bash(git push -u origin feat/spec-:*)` never matches and the capability is silently absent. Allow the command broadly and deny the dangerous forms; verify both directions by running them. | observed 2026-09-26 |
| L-036 | Never run two unattended cycles at once. A second driver switches branches under the first, and uncommitted work from one gets committed by the other. On 2026-09-27 an analyzer change rode into an unrelated pull request that way, weakening the S107 parameter limit from 5 to 30 on `main` unnoticed. The driver now takes a pid lock. | observed 2026-09-27 |
| L-037 | Check `git log main..HEAD` and `git diff --stat main...HEAD` before opening a pull request, not after. A branch cut while HEAD sat on someone else's work carries that work silently, and a pull request body describing only your own change is then wrong without anyone lying. | observed 2026-09-27, PR #12 |
| L-038 | An analyzer threshold can be weakened by a copy-paste while a neighbouring rule is added — both use `<Key>max</Key>`. Numbers in a config file are invisible in review unless something asserts them. Prove a limit fires by writing code that should trip it. | observed 2026-09-27, S107 |
| L-039 | A generated artifact that nothing diffs goes stale silently. `openapi.json` was gated in `agent-check` and stayed correct; the PDFs were not and one shipped a threat register missing two rows. Gate every generated file, or stop generating it. | observed 2026-09-27 |
| L-040 | `git checkout -b` after a concurrent process moved HEAD does not put you where you think. An approval commit landed on `main` instead of the feature branch, the pull request merged only the branch's older commit, and a later `git reset --hard origin/main` discarded the approval entirely. Check `git branch --show-current` after committing, and `git log main..HEAD` before pushing. | observed 2026-09-27, SPEC-004 |
| L-041 | `git reset --hard` is not a safe way to sync a branch that may hold unpushed work. Use `git status` and `git log @{u}..` first; the reflog is the only reason this one was recoverable. | observed 2026-09-27 |
| L-042 | **A broadcast test cannot prove absence by waiting for a timeout.** `AStaleWrite_SendsNothingAsync` attached its listener *after* a write that does broadcast, so the accepted write's message arrived once the handler was on and the test read it as the refused write's: `Assert.Throws() Failure: No exception was thrown`, on CI only, with the same commit passing in another run. Listen before the write you expect, consume its message, then prove the negative with a **fence** — a write that must broadcast, sent after the one that must not. Messages reach a connection in the order the server sent them, so the first to arrive settles it. For a client that left a group, a hub round trip is the barrier: once an invocation returns, anything already sent to that connection has arrived. | observed 2026-10-01, SPEC-016, CI run 36912225779 |
| L-043 | **Stacking spec branches costs more than waiting for a merge.** Twenty-one specs reached `main` through two stacks. The second cost nine hand-retargeted pull requests — GitHub *closes* a child when its base branch is deleted, and a closed one cannot be reopened once that branch is gone, which lost #22 — a landing script whose ordering had to be rewritten twice (the base chain erases itself on retargeting; commit ancestry breaks when a middle branch is rewritten), six conflicts every one of them in `decisions-index.md` or `docs/SDD.md`, five renumbered records, and a flaky test every branch inherited. Cut from `origin/main`. | observed 2026-09-28 and 2026-10-01 to 03 |
| L-044 | **Auto-merge does not make a pull request mergeable; it only presses the button.** With branch protection's `strict` on — *require branches to be up to date* — every merge into `main` puts each open pull request at `mergeStateStatus: BEHIND`, and auto-merge waits there instead of rebasing. The manual step came back one layer down. Merge queue is the instrument that keeps the guarantee and removes the step, and it is refused on a private repository under a personal account: `422 Validation Failed — Invalid rule 'merge_queue'`. See [[ADR-0040-pull-requests-need-not-be-up-to-date]] for what was traded instead. | observed 2026-10-03 |
| L-004 | `reference/` is read-only. It is there to learn the structure from, not to copy from. Backend code is written under `MusicRoom/` only. Copying a file across drags net6-era packages in and breaks subject IV.1 (no third-party source in the repo). | team decision, 2026-09-23 |
