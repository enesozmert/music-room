# Threat Register

Subject V.6 requires more than protections: *"you must identify other dangers and describe the
protection measures that can be implemented"*. This is that document.

**A written accepted risk is an engineering decision. An unwritten one is an oversight.**
Evaluators ask what you did *not* protect against; this table is the answer.

## Status

**Design-stage register.** 32 threats, plus one accepted residual risk recorded in the Accepted section
(T-30, the hub's query-string token). Slice S0 landed the first verified rows, S1 added T-25,
T-26 and T-27, and closed T-25; S1a closed T-26 by landing the hosted mail sender and gave T-19 its
first evidence; S5 closed T-06 — the reorder race subject V.2.3 grades — gave
T-11 and T-12 their first evidence (T-12 narrowed again at S9, when the hub limits landed), and accepted T-30. S6 filled T-17: the location-and-time licence is
enforced, and its residual risk is restated rather than quietly closed. Every other mitigation below is *designed*, not verified.
The Verified column stays empty until a test, a config artifact or a named code path proves it.

## Legend

Likelihood and Impact: L / M / H. Residual = what remains **after** the planned mitigation.

## Explicitly out of scope

| Not defended against | Why |
|---|---|
| A determined attacker with unlimited resources | subject V.6: *"your API is not expected to be unbreakable"* |
| Physical device compromise | the token is in the platform secure store; a rooted device is outside our control |
| Supabase platform compromise | vendor trust boundary, stated rather than pretended away |
| Sybil accounts (T-05) | email verification raises cost; full prevention needs identity proofing this project will not build |
| An access token in a hub URL's query string (T-30) | A WebSocket handshake cannot carry an `Authorization` header, so SignalR documents `access_token` as a query parameter and the mobile client has no other option. Bounded three ways: it is read **only** under `/hubs`, so no REST route gains a second way to authenticate; Serilog's request logging records the path and not the query string, so it does not reach the application log; and the token already lives 15 minutes (ADR-0030, ADR-0032). What remains is that a URL is more copyable than a header — in a crash report, a proxy log the deployment owns, or a shared screen. Accepted on the same ground as the rest of the transport story: TLS is the deployment's job, and the alternative is no realtime on mobile at all (SPEC-016 decision 4) |

## Maintenance

- A finding from [[owasp-top10-checklist]] or [[owasp-api-top10-checklist]] that is not fixed in
  the pull request gets a row here **before** that PR merges.
- Fill Accepted by with a real name when the team agrees to carry a residual risk.
- Fill Verified with the test or artifact that proves the mitigation, once it exists.
- Never delete a row. Close it by pointing at the evidence.
